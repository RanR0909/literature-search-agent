# 部署指南 · 用清华算力券

> 用清华"1000万算力券"里的 **MaaS(大模型平台)** 当大脑 + **云主机** 当运行的地方,
> 把文献领航员几乎零成本搭起来。这是 `README.md` 通用部署方法的一个具体变体(算力和模型都用清华的券)。
> 按顺序做,每步做完打个勾;新手友好,逐条复制粘贴即可。

---

## 你会用到券里的两样(其它别领)

| 领哪个 | 干嘛用 | 备注 |
|---|---|---|
| **大模型平台(MaaS)** | 智能体的"大脑"(DeepSeek/Qwen 等模型 API) | **一定要** |
| **云主机 GPU** | 一台开机运行的云电脑,用来跑 Dify | 要一台(小配置即可,我们不吃 GPU) |
| ~~容器云 GPU / 集群 GPU~~ | 用不上 | 跳过 |

> 说明:我们是"调模型 API",不是"自己训练模型",所以**不需要 GPU 算力**,普通 CPU 就能跑 Dify。GPU 主机是免费的就照用,别纠结。

---

## 阶段 A:先拿到 3 样信息(最关键)

进 MaaS 控制台,找到"API 调用 / 接口 / API Key"之类的地方,**抄下这三样**(后面填进 Dify):

1. **接口地址(base_url)** —— 形如 `https://xxx.xxx/v1`(通常以 `/v1` 结尾)
2. **API Key** —— 一串密钥(`sk-...` 之类),**别外发、别提交到 GitHub**
3. **模型名称(model)** —— 比如 `deepseek-chat`、`qwen-plus` 等(控制台的模型列表里有)

> ✅ 检查点:这三样齐了,才能进下一步。抄不到就点 MaaS 页面里的"帮助文档/使用案例"。

同时确认一件事:**你申请的云主机有没有"公网 IP"、校外能不能访问?**
- 只给自己/校内用 → 无所谓,继续。
- 想让任何人都能打开 → 需要公网 IP;领主机时留意有没有这个选项,没有的话先按"自己用"来,以后再说。

---

## 阶段 B:在云主机上把 Dify 跑起来

领到云主机后,平台会给你一个**登录方式**(网页终端,或 SSH 账号密码)。登录进去,是一个 Linux 命令行。**逐条复制粘贴**下面的命令(遇到问 yes/no 就输 y 回车):

```bash
# 1) 装 Docker(如果主机自带 docker，可跳过这步；先试 docker --version）
curl -fsSL https://get.docker.com | sh

# 2) 下载 Dify
git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env

# 3) 启动 Dify（第一次会下载，等几分钟）
docker compose up -d
```

启动完成后,在浏览器打开:
```
http://<你的云主机IP>/install
```
按提示设置管理员账号密码 → 进入 Dify 后台。

> ✅ 检查点:能打开 Dify 后台页面 = 底座起来了。
> 打不开常见原因:主机"安全组/防火墙"没放行 80 端口 → 在平台的主机网络设置里放行 `80`(和 `443`)。

---

## 阶段 C:在 Dify 里接"清华 MaaS"当大脑

1. Dify 右上角头像 → **设置 → 模型供应商**。
2. 找 **"OpenAI-API-compatible"(OpenAI 兼容)** 这一项 → 添加。
   > (如果列表里直接有 **DeepSeek** 或 **通义千问/Tongyi**,也可以直接选它填 key,更省事。)
3. 按阶段 A 抄的信息填:
   - **API Key**:粘贴你的密钥
   - **API Base / 接口地址**:粘贴 base_url(以 `/v1` 结尾)
   - **模型名称**:填模型名(如 `deepseek-chat`)
4. 保存。

> ✅ 检查点:模型供应商里显示已配置、不报错。

同时再配一个 **Embedding(向量)模型**(知识库检索要用):
- 如果 MaaS 提供 embedding 模型(如 `text-embedding-v3` / `bge` 之类),同样在这里加上;
- 挑一个**支持多语言**的(我们的知识库有 11+ 语种)。

---

## 阶段 D:导入知识库

知识库文件本项目已备好(24 份)。有两种拿到文件的方式:

- **简单**:直接从 GitHub 仓库下载这两个文件夹里的 `.md`:
  `知识库条目-通用版/`(16 份) 和 `公开平台册-上传8份/`(8 份)。
- 或在主机上生成整理好的版本:
  ```bash
  git clone https://github.com/RanR0909/literature-search-agent.git
  cd literature-search-agent
  python3 deploy/prepare_knowledge_base.py    # 生成到 deploy/dist/knowledge-base/
  ```

然后在 Dify:**知识库 → 创建知识库 → 上传**这些 `.md` →
- Embedding 选阶段 C 配的多语言模型;
- 分段方式选"按标题",效果最好。

> ✅ 检查点:知识库里能看到 24 个文档、分段正常。

---

## 阶段 E:接上"实时检索"工具(可选但推荐)

让智能体能实时搜论文(OpenAlex/Crossref/Semantic Scholar)。在**同一台云主机**上再跑我们的检索服务:

```bash
cd literature-search-agent          # 阶段 D 已 clone
docker compose -f deploy/docker-compose.yml up -d --build
curl "http://localhost:8000/health"   # 返回 {"status":"ok"} 即成功
```

然后 Dify:**工具 → 创建自定义工具 → 导入** `tools/search_service/dify_tool_openapi.yaml` →
把里面 `servers.url` 改成 `http://<你的云主机IP>:8000`(记得在主机防火墙放行 `8000` 端口)。

> ✅ 检查点:工具里能测试调用成功。

---

## 阶段 F:建应用、发布

1. Dify → **创建应用 → Chatflow(或 Agent)**。
2. **系统提示词/人设**:把仓库 `prompts/agent_system_prompt.md` 的内容整段粘进去。
3. 挂上 **阶段 D 的知识库** + **阶段 E 的检索工具**。
4. 右上角选**阶段 C 配的模型**(如 DeepSeek)。
5. 点**预览**,自测三个问题:
   - 问一个具体主题("帮我找法国大革命的开放获取文献")→ 看它会不会检索并给链接;
   - 追问细化 → 看它会不会追问国别/时段/语言;
   - 问个查不到的 → 看它会不会老实说没有,而不是编。
6. 没问题 → 点**发布** → 得到一个**网页链接**,分享给别人即可。

> ✅ 检查点:能通过链接跟"文献领航员"对话 = **上线成功** 🎉

## 常见卡点速查

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| Dify 后台打不开 | 防火墙没放行 80 | 平台主机网络设置放行 80/443 |
| 检索工具连不上 | 没放行 8000 端口 | 放行 8000;或让 Dify 和工具走内网 |
| 模型报错/连不上 | base_url 或模型名填错 | 回阶段 A 核对三样信息 |
| 知识库检索不准 | embedding 不是多语言 | 换多语言 embedding 重新建库 |
| 校外打不开链接 | 主机无公网 IP | 确认主机公网访问;或仅校内用 |
