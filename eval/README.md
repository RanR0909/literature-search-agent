# 评测框架(Benchmark)

> 目标:从"能运行"走向"可度量效果"。用一组**黄金问题**对智能体做可重复评测,
> 量化意图路由、工具调用、文献真实性等关键质量维度。这是把项目当产品来做的 eval 思维。

## 七项指标

| 指标 | 含义 | 怎么判 |
|---|---|---|
| **意图路由正确率** | 该查知识库 vs 该实时检索 vs 该先追问,路由是否正确 | 对照每题 `expected_route` |
| **工具调用成功率** | 需要实时检索的题,是否成功调用工具并拿到结果(非报错/非编造) | 看 `tool_called` + 返回是否有真实论文 |
| **文献真实性与链接有效率** | 返回的论文是否真实存在、链接是否可打开 | 抽查 DOI/链接可达性 |
| **知识库引用准确率** | 推荐的平台/说法是否确实来自知识库(引用对得上) | 对照 `retriever_resources` 与知识库原文 |
| **无结果时的诚实降级率** | 查不到时是否如实说明并给替代建议,而非编造 | 看是否出现幻觉链接/平台 |
| **响应时间** | 端到端时延 | 脚本自动记录 `latency_s` |
| **用户任务完成率** | 单题整体上是否真正帮用户达成目标 | 人工 1-5 分 |

## 文件

- `golden_questions.jsonl` —— 黄金问题集(起步模板,建议扩充到 30-50 条)。每条含:
  `id / dimension / question / expected_route / expected_behavior`
- `run_eval.py` —— 评测脚本:逐题调用 Dify 应用 API,记录回答、时延、是否调用工具、引用来源,
  产出 `results/<时间戳>.jsonl`;自动算时延、工具调用、是否带引用,其余维度人工打分。

## 怎么跑

1. 在 Dify 应用里「访问 API」拿到**应用 API Key**(以 `app-` 开头,不是模型 key),并记下 API 基址(形如 `http://<你的服务器>:<端口>/v1`)。
2. 设环境变量后运行(**不要把 key 写进代码或提交**):
   ```bash
   export DIFY_API_BASE="http://<你的服务器>:<端口>/v1"
   export DIFY_API_KEY="app-xxxxxxxx"
   python eval/run_eval.py
   ```
3. 打开 `eval/results/<时间戳>.jsonl`,对需要人工判断的维度(真实性/引用准确/任务完成)逐条打分。
4. 汇总各指标的比例/均值,记录到你的评测报告里;每次改人设/模型/知识库后重跑,对比提升。

## 扩充建议(到 30-50 条)

按维度配比,覆盖多语区与真实使用场景:
- 意图路由:"去哪找平台"类、"帮我查几篇论文"类、信息不全需追问类 各若干;
- 真实性/链接:多给"实时检索"类题,涵盖冷门主题以测试诚实降级;
- 引用准确:多给知识库强相关题(德语区报纸、日本档案、俄语开放平台等);
- 覆盖中/英/多语检索词,测试"中文主题→目标语关键词"的转化。
